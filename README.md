# ВЕТКА СУДЬБЫ: НЕЙРО

Интерактивная нейро-история (киберпанк, 4 дня, 3 исхода). Чистый HTML/CSS/JS — без сборки,
без зависимостей. Открывается двойным щелчком по файлу.

## Как запустить

| Файл | Что это |
|---|---|
| **`standalone.html`** | Всё в одном файле (HTML + CSS + JS). Удобно открыть/скинуть/залить куда угодно. |
| **`index.html`** | Модульная версия: подключает `style.css`, `story.js`, `app.js`. Для разработки и правок. |
| `style.css` | Оформление (тёмный неон, адаптив от 320 px до 1440 px+). |
| `story.js` | **Весь сюжет и контент.** Правится без знания движка. |
| `app.js` | Движок: экраны, диалоги, проверки, ICE-взлом, магазины, сохранения. |

> Для модульной версии нужен локальный сервер (`python3 -m http.server`), иначе некоторые браузеры
> блокируют `localStorage` на `file://`. `standalone.html` работает всегда — при недоступном
> хранилище игра просто не сохраняет прогресс.

## Что реализовано

**Сюжет**
- 4 дня: «Подключение» → «Первый взлом» → «Первая странность» → «Конфликт».
- 56 сюжетных узлов, 20+ развилок, 3 концовки: *Неоновый рассвет*, *Цифровое бессмертие*, *Курьер*.
- Два скрытых финала (память ≥ 30%, взлом ≥ 4) — недоступные варианты видны, но перечёркнуты.

**Механики**
- **Проверки на кубике 0–99:** шанс = база + бонус от стата. Провал — отдельная полноценная ветка, не «try again».
- **Откат «Ветки»:** при провале можно сгладить бросок (−5 Память, +15% шанс). Счётчик откатов виден в «СУБЪЕКТЕ»; на 12-м откате — потеря себя.
- **ICE-взлом:** мини-игра 4×4 — пройти цепочку узлов по горизонтали/вертикали за отведённые секунды. Ошибка отнимает 3 сек.
- **Статы:** Сила, Контроль, Память, Взлом, Хром + Человечность, кредиты, доверие (Никс / Рен / Айрис), репутация фракций.
- **Риппердок и рынок:** покупка имплантов и расходников, реально влияющих на проверки и концовки.
- **Киберпсих:** включается при Памяти ≤ 20% или Контроле ≤ 15% — отдельный экран-слом.
- **Карта,** «Нейро-связь», «Фракции», «Последствия» — живые экраны, данные из пробега.
- **Архив / Аудио:** фрагменты и голосовые записи открываются по ходу сюжета.
- **Сохранения:** 3 ручных слота + автосейв + до 6 «точек возврата» (якорей) на развилках.
- **Архив исходов** с описанием открытых финалов; настройки: скорость текста, размер шрифта, цвет интерфейса, звук/музыка.

**Интерфейс**
- Печать текста (тап/клик — пропустить), стрелки/Enter — дальше, Esc — меню.
- Экранная карточка нового дня, тосты о последствиях, тосты об изменениях статов.
- Адаптив: телефон → планшет → десктоп; сетка чтения превращается в две колонки на широких экранах.
- Учитывает `prefers-reduced-motion`, safe-area (вырез iPhone), отключает hover на тач-устройствах.

## Как править сюжет (`story.js`)

Узел — это объект в `STORY.nodes`. Пример:

```js
d1_01: {
  day: 1, time: '08:14', scene: 'shelter', where: 'УБЕЖИЩЕ',
  checkpoint: 'ВЫХОД ИЗ УБЕЖИЩА',            // необязательно: точка возврата
  enter: {                                    // необязательно: эффекты при входе
    memory: -3, control: +2,
    trust: { nicks: +5 }, rep: { street: +4 },
    flags: { sawArbor: true },
    item: 'чип «АРБОР-2»',
    archive: 'arbor',                         // открыть фрагмент архива
    unlockAudio: 'a3',                        // открыть аудиозапись
    cons: { time:'08:17', cls:'lime', title:'…', effects:'…', desc:'…' }
  },
  lines: [
    ['narrator', 'Текст от автора.'],
    ['kai', 'Реплика Кая.'],
    ['system', 'СИСТЕМНОЕ СООБЩЕНИЕ // КАНАЛ']
  ],
  choice: {
    header: '◈ [ РАЗВИЛКА ] // МЕСТО',
    question: 'Вопрос к игроку',
    options: [
      { tag:'[ПАМЯТЬ]', text:'Вспомнить', cls:'success',
        check:true, base:40, stat:'memory',
        success:'d1_mem_ok', fail:'d1_mem_fail' },

      { tag:'[ВЗЛОМ]', text:'Вскрыть терминал', cls:'warn',
        hack:true, success:'d1_hack_ok', fail:'d1_hack_fail',
        hackCfg:{ targets:['A7','C2','77','42'], time:22, sub:'ТЕРМИНАЛ' } },

      { tag:'[ОТКАЗ]', text:'Уйти', cls:'danger',
        effects:{ control:+4, trust:{ iris:-6 } },
        next:'d1_exit' },

      { tag:'[ФИНАЛ]', text:'Сжечь «Арбор»', cls:'success',
        req:{ key:'memory', min:30, hint:'НУЖНА ПАМЯТЬ 30%' },
        success:'end_dawn' }                      // id узла-финала
    ]
  }
}
```

- `next` — следующий узел. Для финальных узлов достаточно `ending: 'dawn'`.
- Хак-узел: `hack: { targets:[…], time:30, sub:'…', success:'…', fail:'…' }` без `lines`.
- Кибер-узел: `cyber: { sub, text, panels:[{cls,title,desc}] }` — показывается как экран.
- Персонажи — в `STORY.characters` (имя, роль). Цвет берётся из CSS-класса по id персонажа
  (`.kai`, `.nicks`, `.iris`…), так что нового героя достаточно добавить в `characters` и в
  цветовые переменные.
- Предметы магазина — `STORY.market`, импланты — `STORY.implantStore`, аудио — `STORY.audio`,
  архив — `STORY.archive`, исходы — `STORY.endings`, локации карты — `STORY.locations`.

**Проверка целостности.** После правок удобно прогнать скрипт, который сверяет все ссылки
`next/success/fail` с существующими узлами (я использовал именно такой при разработке).

## Эффекты (`effects` / `enter`)

| Ключ | Смысл |
|---|---|
| `force, control, memory, hack, chrome, creds, humanity` | числовые статы (со знаком) |
| `trust: { nicks, ren, iris, silva }` | доверие 0–100 |
| `rep: { street, netrunners, sylva, relics }` | репутация фракций 0–100 |
| `flags: { … }` | сюжетные флаги |
| `item`, `removeItem` | инвентарь |
| `archive`, `unlockAudio` | открыть фрагмент/запись |
| `removeImplant` | удалить имплант (сюжетное удаление «Ветки») |
| `cons` | запись в «ПОСЛЕДСТВИЯ» |
| `day`, `location` | день и текущая точка на карте |

## Структура экранов

`screen-menu`, `screen-chapters`, `screen-reading`, `screen-choice`, `screen-subject`,
`screen-ripperdoc`, `screen-cyberpsych`, `screen-consequences`, `screen-map`, `screen-system`,
`screen-endings`, `screen-links`, `screen-factions`, `screen-market`, `screen-returns`,
`screen-audio`, `screen-archive`, `screen-finale` + оверлеи: ICE, кубик, боковое меню, тосты, модалки.

## Что можно добавить дальше

- Звук/музыка (WebAudio-синтез или mp3) — слайдеры уже есть, движок к ним пока не подключён.
- Больше дней/побочных контрактов — движок это поддерживает: просто добавьте узлы и день в `STORY.days`.
- Портреты персонажей картинками: `renderReading()` уже собирает `.character-portrait` —
  достаточно подставить `<img>` вместо глифа.
